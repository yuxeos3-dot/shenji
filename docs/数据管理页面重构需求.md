# 数据管理页面（DataManagement）重构需求文档

## 一、背景与现状问题

### 当前实现

`frontend/src/views/DataManagement.vue` 是一个 **iframe 包装器**，嵌入了 `frontend/public/gsc-dashboard.html`（约1000行的独立HTML页面）。

```vue
<!-- 当前代码 —— 仅3行模板 -->
<template>
  <div class="dm-wrap">
    <iframe src="/gsc-dashboard.html" class="dm-frame" />
  </div>
</template>
```

### 三大问题

| 问题 | 原因 | 用户感知 |
|------|------|----------|
| **加载极慢** | iframe 每次加载都要拉取 Google Fonts CDN、Chart.js CDN、Google Sign-In API 三个外部资源 | 进入页面等3-5秒才能用 |
| **切换页面数据丢失** | Vue router 切换时 iframe DOM 被销毁，回来后重建，需要重新走 Google OAuth 登录 + 重新拉取所有数据 | 切到其他页面再回来，数据全没了 |
| **与后端割裂** | 后端已有 `/api/v1/sites/:id/gsc`、`/ga`、`/bing`、`/yandex` 接口存储了同步数据，但 iframe 里是独立走 Google API 直连 | 两套数据源、两套认证，容易不一致 |

---

## 二、重构目标

用 **纯 Vue 组件** 替换 iframe，直接调用后端已同步的数据 API。

### 核心改进

1. **秒开**：数据来自自己的后端数据库（SQLite），不依赖任何外部 CDN
2. **切换不丢数据**：使用 Vue `<KeepAlive>` 缓存组件状态
3. **站点级内存缓存**：切换站点后，已加载过的数据缓存在 JS 内存中，切回不重复请求
4. **统一数据源**：与后端系统完全一致，数据来自 `gsc_data`、`ga_data`、`bing_data`、`yandex_data` 表

### 3.2 四个 Tab 的数据展示

#### GSC Tab
- **统计卡片**：总点击、总展示、平均CTR、平均排名（4列）
- **趋势表格**：日期 | 点击 | 展示 | CTR | 排名 | 热门关键词（取 keywords_json 前3个）

## 四、涉及的后端 API

所有 API 已存在，**无需修改后端**。

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/sites` | GET | 获取站点列表 |
| `/api/v1/sites/:id/gsc?days=30` | GET | 获取 GSC 数据（最近N天） |
| `/api/v1/sites/:id/ga` | GET | 获取 GA 数据 |
| `/api/v1/sites/:id/bing` | GET | 获取 Bing 数据 |
| `/api/v1/sites/:id/yandex` | GET | 获取 Yandex 数据 |
| `/api/v1/sites/:id/gsc/sync` | POST | 同步 GSC 数据 |
| `/api/v1/sites/:id/ga/sync` | POST | 同步 GA 数据 |
| `/api/v1/sites/:id/bing/sync` | POST | 同步 Bing 数据 |
| `/api/v1/sites/:id/yandex/sync` | POST | 同步 Yandex 数据 |

## 五、涉及文件

| 文件 | 改动说明 |
|------|----------|
| `frontend/src/views/DataManagement.vue` | **完全重写**：从3行 iframe 改为完整 Vue 组件 |

### Layout.vue 改动要点

```vue

<div class="page-body">
  <router-view v-slot="{ Component }">
    <keep-alive include="DataManagement">
      <component :is="Component" />
    </keep-alive>
  </router-view>

<!-- 改动2：侧边栏链接（当前是 <a> 标签新窗口打开，改为 router-link） -->
<li>
  <router-link to="/data-management" :class="{active: $route.path==='/data-management'}">
    <span class="nav-icon">📡</span>数据管理
  </router-link>
</li>
```

### DataManagement.vue 组件名声明

```vue
<!-- 必须声明 name 才能被 KeepAlive include 匹配 -->

</script>
```

## 六、关键实现逻辑

### 6.1 数据加载流程

```
页面挂载 (onMounted)
  → 请求站点列表 listSites()
  → 默认选中第一个站点
  → 并发请求4个平台数据 Promise.all([gsc, ga, bing, yandex])
  → 存入响应式变量 + 缓存到 cache[siteId]
```

### 6.2 站点切换

```
用户切换站点
  → 检查 cache[newSiteId] 是否存在
  → 有缓存 → 直接从缓存赋值（瞬间切换）
  → 无缓存 → 显示 loading → 并发请求4个API → 存入缓存
```

### 6.3 同步操作

```
用户点「同步当前数据源」
  → 根据当前 activeTab 调用对应 sync API
  → 清除该站点缓存
  → 重新加载数据（强制刷新）
```

### 6.4 JSON 子数据解析

后端返回的 `keywords_json`、`channels_json`、`pages_json` 等字段是 JSON 字符串，需要在前端解析。用 computed 属性处理：

```javascript
const gaChannels = computed(() => {
  try {
    const raw = gaData.value[0]?.channels_json
    const parsed = typeof raw === 'string' ? JSON.parse(raw) : raw
    const rows = parsed?.rows || []
    return rows.map(r => ({
      dim: r.dimensionValues?.[0]?.value || '—',
      sessions: +r.metricValues?.[0]?.value || 0,
      users: +r.metricValues?.[1]?.value || 0,
      pageviews: +r.metricValues?.[2]?.value || 0,
    })).sort((a, b) => b.sessions - a.sessions)
  } catch { return [] }
})
```

## 七、视觉风格要求

- 沿用系统现有的 CSS 变量体系（`--sun`、`--coral`、`--surface`、`--border-light` 等）
- 统计卡片使用 grid 布局，自适应列数
- 数字用 `JetBrains Mono` 等宽字体
- 颜色区分：点击=蓝色(`--info`)、展示=绿色(`--ok`)、CTR=橙色(`--warn`)、排名=紫色(`#7C3AED`)
- 表格行 hover 高亮为 `var(--sun-light)`
- Tab 切换使用药丸按钮（pill），选中态为渐变橙色
- 空状态显示引导文字，告知用户下一步操作

## 八、测试要点

1. **首次进入**：选中第一个站点，四个平台数据并发加载
2. **Tab 切换**：GSC → GA → Bing → Yandex 之间切换，数据不丢失
3. **站点切换**：切换到另一个站点后数据更新；切回来使用缓存
4. **路由切换**：去其他页面（如站点管理）再回来，数据保持（KeepAlive）
5. **同步操作**：点同步后数据刷新，缓存清除
6. **空数据**：站点无 GSC/GA/Bing/Yandex 数据时显示引导提示
7. **错误处理**：API 失败时显示 ElMessage.error
8. **响应式**：窄屏下双栏变单栏，工具栏自动换行
